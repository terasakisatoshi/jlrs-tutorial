# ターゲット

前の章では、スコープ内でのみJuliaと対話できることを見てきました。ここでは、フレームを使用して管理されたデータをルートすることができます。フレームを使用して呼び出したメソッドのシグネチャを見ると、これらのメソッドはジェネリックであり、`Target`トレイトを実装する任意の型のインスタンスを取ることができることがわかります。戻り値の型もこのターゲット型に依存します。

例えば、`Call::call0`のシグネチャを見てみましょう：

```rust,ignore
unsafe fn call0<'target, Tgt>(self, target: Tgt) -> ValueResult<'target, 'data, Tgt>
    where
        Tgt: Target<'target>;
```

`Target`を実装する任意の型はターゲットと呼ばれます。ターゲットがエンコードするものは2つあります：結果がルートされているかどうか、そしてそれに適用されるライフタイム制約です。

`&mut frame`を使って`call0`を呼び出すと、`ValueResult`は`Result<Value, Value>`です。`&frame`も`Target`を実装しており、それを使って`call0`を呼び出すと、結果はルートされず、`ValueResult`は`Result<ValueRef, ValueRef>`になります。`&mut frame`はルート化ターゲットであり、`&frame`は非ルート化ターゲットと言います。

`Value`と`ValueRef`の違いは、`Value`はルートされていることが保証されているのに対し、`ValueRef`はそうではないことです。`ValueRef`を意味のある方法で使用するのは安全ではありません。型レベルでルート化されたデータとルート化されていないデータを区別することで、ルート化されていないデータの誤用を避け、デバッグが難しいuse-after-freeの問題に陥るのを防ぎます。すべての管理された型には`Ref`エイリアスがあり、これらの型のインスタンスを管理されたデータへのルート化されていない参照と呼びます。

`Result`エイリアスは例外をキャッチする関数で使用され、それ以外の場合は`ValueData`が使用されます。`ValueResult`は`Result<ValueData, ValueData>`として定義されています。すべての管理された型には`Result`と`Data`エイリアスがあります。
